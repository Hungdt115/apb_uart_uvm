```yaml
summary: >
  UART transmitter with integrated TX FIFO and an 8-functional-block RTL
  architecture. The transmitter uses a dedicated FSM, bit/stop counters,
  frame configuration logic, TX data generation logic, and uart_baud_gen
  clock-enable ticks.
```

---

# 1. Overview

`uart_tx` is the UART transmitter core. It contains:

- A `sync_fifo` instance for buffering transmit data.
- A TX FIFO controller that performs the pop → hold → start sequence.
- A baud-rate generator (`uart_baud_gen`) producing `w_cken`.
- A state-transition FSM.
- Dedicated bit and stop counters.
- Dedicated frame configuration logic for parity and stop bits.
- Dedicated TXD and shift-register logic.
- FIFO and transmitter status generation.

The APB side pushes bytes through `REG_UART_TXD` / `REG_UART_TX_WEN`. The transmitter serializes the buffered bytes through `O_TXD`, LSB first.

The entire design is synchronous to `I_CLK`. The `w_cken` signal is a one-cycle clock enable generated by the baud generator. It is not used as a clock.

The internal RTL is organized into 8 functional blocks. These blocks are separate logical sections within the same `uart_tx` module and do not introduce additional submodules, except for the existing `sync_fifo` and `uart_baud_gen` instances.

# 2. Parameters

| Parameter | Type | Default | Description |
|---|---|---:|---|
| `DATA_BITS` | Integer | 8 | Number of data bits per frame |
| `TX_FIFO_DEPTH` | Integer | 32 | TX FIFO depth |

The default UART frame format is **8N1**:

- 1 start bit
- 8 data bits, LSB first
- No parity
- 1 stop bit

This corresponds to `I_MODE = 4'b0000`.

# 4. Transmitter FSM

## 4.1 States

| State | Encoding | Description | TXD behavior |
|---|---|---|---|
| `S_IDLE` | `3'd0` | Waiting for a transmit frame | 1 |
| `S_START` | `3'd1` | Start-bit period | Start/data transition logic |
| `S_DATA` | `3'd2` | Data transmission | Data bits |
| `S_PARITY` | `3'd3` | Parity transmission | Parity bit |
| `S_STOP` | `3'd4` | Stop-bit period(s) | 1 |

The FSM is responsible for state transitions only.

The FSM does not directly assign:

- `txd`
- `shift_reg`
- `bit_cnt`
- `stop_cnt`
- `parity_bit`
- `stop_target`

These registers are controlled by their respective functional blocks.

## 4.2 State transitions

```text
S_IDLE
    |
    | r_tx_start
    v
S_START
    |
    | w_cken
    v
S_DATA
    |
    | w_data_done
    +---------------------> S_PARITY (if I_MODE[1] = 1)
    |
    +---------------------> S_STOP   (if I_MODE[1] = 0)

S_PARITY
    |
    | w_cken
    v
S_STOP
    |
    | w_stop_done
    v
S_IDLE
```

Transition conditions:

| Current state | Condition | Next state |
|---|---|---|
| `S_IDLE` | `r_tx_start` | `S_START` |
| `S_IDLE` | Otherwise | `S_IDLE` |
| `S_START` | `w_cken` | `S_DATA` |
| `S_START` | Otherwise | `S_START` |
| `S_DATA` | `w_data_done` and parity enabled | `S_PARITY` |
| `S_DATA` | `w_data_done` and parity disabled | `S_STOP` |
| `S_DATA` | Otherwise | `S_DATA` |
| `S_PARITY` | `w_cken` | `S_STOP` |
| `S_PARITY` | Otherwise | `S_PARITY` |
| `S_STOP` | `w_stop_done` | `S_IDLE` |
| `S_STOP` | Otherwise | `S_STOP` |

The FSM is independent of TXD shifting and counter implementation.

## 4.3 Completion flags

The FSM uses two completion flags:

- `w_data_done`: indicates the final data-bit transmission tick.
- `w_stop_done`: indicates the stop counter has reached its configured terminal condition.

These flags are generated by Functional Block 2.

# 5. Bit Counter and TX Data Generation

## 5.1 Bit counter

The bit counter is implemented independently of the FSM.

`bit_cnt` uses a 4-bit register and follows the counting convention:

```text
0 → 1 → 2 → ... → 8
```

Behavior:

- Reset to `0` on asynchronous reset.
- Reset to `0` on frame load (`w_ld_frame`).
- Increment on the START baud tick.
- Increment on each DATA baud tick.
- Hold its value when no applicable baud tick occurs.

The START tick increments the counter from 0 to 1. The subsequent DATA ticks increment it until it reaches 8.

The final data-bit completion flag is:

```verilog
w_data_done = (state == S_DATA) &&
              w_cken &&
              (bit_cnt == DATA_BITS - 1);
```

The counter convention is changed from the original organization to make the transmitted-bit progress explicit, while the data-bit output sequence and intended baud timing remain unchanged.

## 5.2 Shift register

The shift register is controlled exclusively by Functional Block 7.

On frame load (`w_ld_frame`):

```verilog
shift_reg <= r_tx_data_hold;
```

On each applicable baud tick during START/DATA transmission:

```verilog
txd       <= shift_reg[0];
shift_reg <= {1'b0, shift_reg[DATA_BITS-1:1]};
```

The transmitter outputs data LSB first.

The shift register shifts right, inserting zero at the MSB position.

## 5.3 Start bit

The start bit is generated when `w_ld_frame` is asserted while the FSM is in `S_IDLE`.

```verilog
txd <= 1'b0;
```

The frame-load event is shared across the bit counter, frame configuration, and TX data generation blocks.

## 5.4 Parity generation

Parity is configured at runtime through `I_MODE[2:1]`.

Parity is calculated from the held transmit data byte and latched when `w_ld_frame` is asserted.

The parity bit is output in `S_PARITY` on a baud tick.

Parity output behavior:

```verilog
if (w_cken)
    txd <= parity_bit;
```

The parity calculation and configuration are implemented in Functional Block 6.

## 5.5 Stop-bit generation

Stop-bit configuration is controlled by `I_MODE[0]`.

```verilog
stop_target = I_MODE[0] ? 2'd2 : 2'd1;
```

| `I_MODE[0]` | Configured stop bits | `stop_target` |
|---|---:|---:|
| 0 | 1 | 1 |
| 1 | 2 | 2 |

The stop counter is reset on frame load and counts baud ticks during `S_STOP`.

`txd` is driven high throughout the STOP state.

**Counter terminal behavior:** In the current RTL, `w_stop_done` is asserted when `stop_cnt == stop_target` and `w_cken` is active. Since the counter starts at zero and increments before the terminal comparison is satisfied, the current implementation consumes `stop_target + 1` stop ticks (2 ticks for target 1, 3 ticks for target 2). This behavior must be confirmed before treating the stop timing as final.

## 5.6 TX busy

```verilog
O_TX_BUSY = (state != S_IDLE);
```

`O_TX_BUSY` is combinationally derived from the FSM state.

It is asserted throughout the active transmitter states, including START, DATA, PARITY (when enabled), and STOP.

It deasserts when the FSM transitions to `S_IDLE`.

# 6. MODE Encoding (`I_MODE[3:0]`)

`I_MODE[3:0]` is mapped to `REG_UART_MODE[3:0]`.

| Bit | Field | Value 0 | Value 1 |
|---|---|---|---|
| `MODE[0]` | `STOP_BITS` | 1 stop bit | 2 stop bits |
| `MODE[1]` | `PARITY_EN` | No parity | Parity enabled |
| `MODE[2]` | `PARITY_ODD` | Even parity | Odd parity |
| `MODE[3]` | Reserved | Must be 0 | Reserved |

Configuration examples:

| `I_MODE` | Format |
|---|---|
| `4'b0000` | 8N1 |
| `4'b0010` | 8E1 |
| `4'b0100` | 8O1 |
| `4'b0001` | 8N2 |
| `4'b0011` | 8E2 |
| `4'b0101` | 8O2 |

- `I_MODE = 0` is the default 8N1 configuration.
- `DATA_BITS` is a compile-time parameter.
- Parity and stop configuration are captured at frame load.
- `I_MODE` should remain stable during a frame. The current FSM uses `I_MODE[1]` at the data-completion transition, so changing mode mid-frame is not guaranteed to be handled consistently with the previously latched parity configuration.

# 7. Integrated TX FIFO

## 7.1 Instance

The TX FIFO is implemented using `sync_fifo`.

```verilog
sync_fifo #(
    .DW    (8),
    .DEPTH (TX_FIFO_DEPTH)
) u_tx_fifo (
    .I_CLK          (I_CLK),
    .I_RST          (I_RST_N),
    .I_CLR          (w_tx_fifo_clr),
    .I_WR_EN        (fifo_wen),
    .I_WR_DATA      (I_TX_WR_DATA),
    .I_RD_EN        (fifo_ren),
    .O_RD_DATA      (fifo_rd_data),
    .O_FULL         (fifo_full),
    .O_EMPTY        (fifo_empty),
    .O_ALMOST_FULL  (fifo_almost_full),
    .O_ALMOST_EMPTY (),
    .O_COUNT        (fifo_count)
);
```

The FIFO stores 8-bit transmit bytes.

Default configuration:

- Width: 8 bits
- Depth: 32 bytes

## 7.2 Write path (APB → FIFO)

```verilog
fifo_wen = I_TX_WR_EN;
```

FIFO writes are not gated by `I_UART_EN`.

Software may preload the FIFO while the UART transmitter is disabled.

Overflow behavior:

- If `fifo_full` and `fifo_wen` are asserted at a clock edge, `r_tx_ovf` is set.
- `r_tx_ovf` is sticky.
- It is cleared by asynchronous reset or FIFO flush.
- `O_TX_OVF` reflects the sticky overflow flag.

The FIFO itself handles writes while full according to `sync_fifo` behavior.

## 7.3 FIFO flush

The flush signal is edge-detected:

```verilog
w_tx_fifo_clr = I_TX_FIFO_CLR & ~r_clr_d;
```

A rising edge of `I_TX_FIFO_CLR` generates a one-cycle clear pulse.

Flush behavior:

- Clears buffered FIFO entries.
- Clears the sticky overflow flag.
- Cancels a pending FIFO pop operation by resetting the TX controller phase.
- Does not abort a frame already in progress.
- To trigger another flush, `I_TX_FIFO_CLR` must first return low and then rise again.

The flush signal is connected to the FIFO clear input.

## 7.4 TX controller — pop, hold, start

The FIFO read data is registered. The TX controller therefore uses three phases:

| Phase | Symbol | Operation |
|---|---|---|
| Wait | `C_WAIT` | Wait for transmit start condition |
| Hold | `C_HOLD` | Capture registered FIFO read data |
| Start | `C_START` | Assert `r_tx_start` for frame loading |

The controller sequence is:

| Cycle | Event |
|---|---|
| N | Start condition met: FIFO is not empty, transmitter is not busy, and `I_UART_EN` is high. Assert FIFO read enable. |
| N+1 | Capture the registered FIFO read data into `r_tx_data_hold`. |
| N+2 | Assert `r_tx_start`; `w_ld_frame` is asserted to load the transmit frame. |

Start condition:

```verilog
w_start_cond = ~fifo_empty & ~w_tx_busy & I_UART_EN;
```

FIFO read enable:

```verilog
fifo_ren = (ctrl_phase == C_WAIT) & w_start_cond;
```

Frame start:

```verilog
r_tx_start = (ctrl_phase == C_START);
```

Frame-load event:

```verilog
w_ld_frame = r_tx_start;
```

`w_ld_frame` is the common load event used by Functional Blocks 2, 6, and 7.

Flush resets the controller to `C_WAIT`, cancelling a pending pop/hold/start transaction. A frame that has already entered the shifter FSM is not aborted by flush.

## 7.5 Status outputs

| Output | Source | Description |
|---|---|---|
| `O_TX_BUSY` | `state != S_IDLE` | Transmitter active |
| `O_TX_IDLE` | `fifo_empty && !w_tx_busy` | FIFO empty and transmitter idle |
| `O_TX_OVF` | `r_tx_ovf` | Sticky overflow status |
| `O_TX_FIFO_ALMOST_FULL` | `fifo_almost_full` | FIFO almost-full status |
| `O_TX_FIFO_FULL` | `fifo_full` | FIFO full |
| `O_TX_FIFO_EMPTY` | `fifo_empty` | FIFO empty |
| `O_TX_FIFO_COUNT` | `fifo_count` | FIFO occupancy |

`O_TX_IDLE` indicates that no buffered data remains and the transmitter has completed its current frame.

## 7.6 Enable behavior

The baud generator enable is connected as:

```verilog
I_ENABLE = w_tx_busy | I_UART_EN;
```

Consequently:

- When `I_UART_EN = 1`, the baud generator is enabled, including while the transmitter is idle.
- When `I_UART_EN = 0` and the transmitter is idle, the baud generator is disabled and its counters are reset.
- When `I_UART_EN = 0` but `w_tx_busy = 1`, the baud generator remains enabled so the active frame can continue to receive baud ticks.
- FIFO writes remain enabled independently of `I_UART_EN`.
- The FIFO pop/start condition remains gated by `I_UART_EN`.

Disabling `I_UART_EN` prevents new frames from being started, but does not stop the baud generator from progressing through an already active frame.

## 7.7 Reset behavior

Asynchronous active-low reset (`I_RST_N`):

- FSM → `S_IDLE`.
- `txd` → 1.
- `shift_reg` → 0.
- Bit counter and stop counter → 0.
- TX controller phase → `C_WAIT`.
- Hold data → 0.
- Parity bit → 0.
- Stop target → default 1.
- Flush edge-detection register → 0.
- Overflow flag → 0.
- FIFO is reset through its reset input.
- Baud generator is reset to its default divisor.

# 8. Baud-Generator Instantiation

The TX core instantiates `uart_baud_gen`.

```verilog
uart_baud_gen u_tx_baud_gen (
    .I_CLK        (I_CLK),
    .I_RST_N      (I_RST_N),
    .I_BRG_DIV    (I_BRG_DIV),
    .I_BRG_WR_EN  (I_BRG_WR_EN),
    .I_ENABLE     (w_tx_busy | I_UART_EN),
    .I_RESTART    (r_tx_start),
    .O_TICK_16X   (),
    .O_TICK_1X    (w_cken)
);
```

| Signal | Connection | Description |
|---|---|---|
| `I_ENABLE` | `w_tx_busy \| I_UART_EN` | Enable baud generation while UART enabled or frame active |
| `I_RESTART` | `r_tx_start` | Restart baud phase at frame load |
| `O_TICK_16X` | Unconnected | Not used by TX |
| `O_TICK_1X` | `w_cken` | Bit-period clock enable |

The `w_cken` pulse is used to advance the TX FSM and bit-level operations.

The baud generator resets its counters when disabled. Divisor writes restart the baud phase according to the `uart_baud_gen` implementation. Divisor updates should preferably occur while TX is idle.

# 9. Internal Architecture — 8 Functional Blocks

The internal RTL is organized into eight functional blocks. Each block is implemented using dedicated `always` and/or `assign` sections within the same `uart_tx` module.

No additional submodules are created for these blocks.

| # | Functional block | Internal signals | Responsibility |
|---|---|---|---|
| 1 | Baud enable generation | `u_tx_baud_gen`, `w_cken`, `w_tx_busy` | Instantiate baud generator and produce bit-period enable |
| 2 | Bit counter | `bit_cnt`, `stop_cnt`, `w_data_done`, `w_stop_done` | Track transmitted data bits and stop periods |
| 3 | FSM control | `state`, `r_tx_start`, `w_cken`, `w_data_done`, `w_stop_done`, `I_MODE[1]` | Control state transitions only |
| 4 | Send data generation / FIFO write | `r_clr_d`, `w_tx_fifo_clr`, `fifo_wen`, `r_tx_ovf` | FIFO write, flush edge detection, sticky overflow |
| 5 | Data buffer pop | `u_tx_fifo`, `ctrl_phase`, `r_tx_data_hold`, `fifo_ren`, `r_tx_start` | FIFO pop → hold → start transaction |
| 6 | Start/parity/stop generation | `w_parity_next`, `w_stop_target_next`, `parity_bit`, `stop_target`, `w_ld_frame` | Generate and latch frame configuration |
| 7 | Transmit data generation | `txd`, `shift_reg`, `w_ld_frame`, `w_cken`, `state` | Generate start, data, parity, and stop output |
| 8 | Status flags | `w_tx_busy`, `O_TX_BUSY`, `O_TX_IDLE`, `O_TX_OVF`, `FIFO_*` | Provide transmitter and FIFO status |

## 9.1 Block interaction

```text

                 | 1. Baud Generation  |
                 | uart_baud_gen       |
                 |       w_cken        |
                 +----------+-----------+
                            |
                            v
                 +----------------------+
                 | 2. Bit Counters     |
                 | bit_cnt / stop_cnt   |
                 | data_done/stop_done  |
                 +----------+-----------+
                            |
                            v
                 +----------------------+
                 | 3. FSM Control      |
                 | State transitions    |
                 +----------+-----------+
                            |
                            v
                 +----------------------+
                 | 7. TX Data          |
                 | txd / shift_reg     |
                 +----------------------+

  +---------------------+       +----------------------+
  | 4. FIFO Write/     |       | 5. Data Buffer Pop  |
  | Flush/Overflow     |------>| sync_fifo + control |
  +---------------------+       +----------+-----------+
                                          |
                                          v
                                 r_tx_data_hold
                                          |
                                          v
                                    r_tx_start
                                          |
                                          v
                                 +--------------------+
                                 | 6. Frame Config   |
                                 | Parity / Stop      |
                                 +--------------------+

                                 +--------------------+
                                 | 8. Status Flags   |
                                 | Busy / Idle / FIFO |
                                 +--------------------+
```

The diagram shows functional relationships only. All eight blocks reside within the same `uart_tx` module.

```text
I_TX_WR_EN   : ___/‾\________________________________________
                 Push byte A

FIFO count   : 0   1   1   1   1   1   1   1   ...

fifo_ren     : __________/‾\_______________________________
                 N: pop

FIFO RD_DATA : _____________<---- A ------------------------
                 N+1: registered data available

r_tx_start   : ____________________/‾\_____________________
                 N+2: frame-start event

w_ld_frame   : ____________________/‾\_____________________
                 Shared frame-load event

O_TX_BUSY    : ____________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
                 Active from START until STOP completion

O_TXD       : ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
                 Start | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | Stop

w_cken      : ............ pulse every bit-period
```

Timing notes:

- FIFO pop → hold → start follows the three-phase controller sequence.
- `w_ld_frame` is asserted with `r_tx_start`.
- Frame loading sets `txd` low to start the frame and loads the data shift register.
- The first baud tick in START outputs D0.
- Subsequent DATA baud ticks output D1 through D7.
- Parity is transmitted only when parity is enabled.
- Stop output is high.
- `O_TX_BUSY` remains high until the FSM returns to `S_IDLE`.

The exact edge-to-edge latency should be verified using the RTL and FIFO registered-read timing. The timing diagram is a functional illustration rather than a cycle-accurate waveform.

# 12. Implementation Constraints

- Keep the `uart_tx` port list unchanged.
- Maintain the 8-functional-block architecture.
- Each block must remain a logical section inside the module, not a submodule.
- Keep `LOCALPARAMS`, `REGS`, `WIRES`, and `CONTINUOUS ASSIGNS` grouped near the beginning of the file.
- FSM block must only manage state transitions.
- Each register must have a single sequential driver.
- Maintain the FIFO pop → hold → start sequence.
- Flush must cancel a pending pop transaction.
- Flush must not abort an active frame.
- `w_ld_frame` must remain the common frame-load event.
- Keep baud ticks as clock enables, not generated clocks.
- Maintain consistency between RTL and this specification.
- Any changes to timing, counter terminal conditions, or external behavior must be documented and verified.

# 14. Notes and Known RTL Discrepancies

The following items must be resolved or confirmed before the specification is considered final:

1. **Stop-counter terminal count:** Current RTL terminal comparison causes the stop counter to consume `stop_target + 1` baud ticks. This is inconsistent with the intended 1-stop-bit/2-stop-bit duration.
2. **Mode stability:** `I_MODE` should remain stable while a frame is active. The parity and stop configuration are latched, but the FSM parity transition uses `I_MODE[1]` directly.
3. **TXD timing:** Verify the start bit, first data bit, and subsequent data bits against cycle-accurate simulation.
4. **FIFO simultaneous flush/write:** Confirm `sync_fifo` behavior when flush and write occur on the same clock edge.
5. **Baud divisor update:** A divisor write restarts the baud timing phase. Software should preferably update the divisor while TX is idle.
6. **Busy/start interaction:** Confirm `O_TX_BUSY` assertion and first start-bit edge in the integrated waveform.

The specification should be finalized only after the RTL simulation confirms these behaviors.
